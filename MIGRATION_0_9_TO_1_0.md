# Migrating PyPageKit 0.9.x to 1.0

This guide is the canonical migration document for the final pre-1.0 release line.

At `0.9.0b1`, PyPageKit has **no active public deprecations** and no intentional public API rename
requiring code changes. The primary migration task is to ensure applications depend only on the
inventoried public contract before the `1.0.0` freeze.

## 1. Use canonical facade imports

Preferred:

```python
from pypagekit import Page, Paragraph, Route, Site
from pypagekit.build import StaticSiteGenerator
from pypagekit.components import ComponentRegistry
from pypagekit.extensions import RendererRegistry
from pypagekit.rendering import HtmlRenderer
```

Avoid deep implementation imports:

```python
from pypagekit.build.generator import StaticSiteGenerator
from pypagekit.components.registry import ComponentRegistry
from pypagekit.extensions.registry import RendererRegistry
from pypagekit.rendering.html import HtmlRenderer
```

Deep imports are not independently covered by the compatibility promise.

## 2. Treat the Python CLI adapter as provisional

For automation, prefer the installed CLI:

```bash
pypagekit --version
pypagekit new .
pypagekit doctor
pypagekit inspect
pypagekit serve
```

or:

```bash
python -m pypagekit
```

Do not build application architecture around the concrete Typer object unless you intentionally
accept its provisional status:

```python
from pypagekit.cli import app
```

The shell command contract is the stable-candidate operational surface.

## 3. Enable deprecation warnings in CI

PyPageKit uses standard `DeprecationWarning`.

Before upgrading to 1.0, enable warnings in tests:

```bash
python -W default::DeprecationWarning -m pytest
```

For stricter migration gates:

```bash
python -W error::DeprecationWarning -m pytest
```

At `0.9.0b1`, no PyPageKit public deprecation warning should be emitted by normal supported usage.

## 4. Plugin authors: declare the extension API explicitly

Plugin descriptors should declare:

```python
from pypagekit.extensions import (
    PYPAGEKIT_EXTENSION_API_VERSION,
    ExtensionDescriptor,
)

descriptor = ExtensionDescriptor(
    "acme.renderer.custom",
    "ACME Renderer",
    "1.0.0",
    api_version=PYPAGEKIT_EXTENSION_API_VERSION,
)
```

The current extension compatibility line is:

```text
0.7
```

Use the exported constant instead of hard-coding the value where possible.

Entry-point groups remain:

```text
pypagekit.renderers
pypagekit.build_planners
pypagekit.components
```

## 5. Do not depend on internal extension modules

Use:

```python
from pypagekit.extensions import (
    BuildPlannerExtension,
    ComponentExtension,
    RendererExtension,
)
```

rather than importing from `pypagekit.extensions.model`, `registry`, or `discovery` directly.

## 6. Catch public exceptions through public facades

Preferred:

```python
from pypagekit.exceptions import BuildError, UnsafeUrlError
```

or subsystem-specific public facades such as:

```python
from pypagekit.project import ProjectScaffoldingError
```

Avoid depending on physical exception-module layout.

## 7. Generated projects

Projects generated by PyPageKit `0.9.0b1` use a requirement on the current pre-1.0 minor line:

```text
pypagekit>=0.9.0b1,<0.10
```

Before adopting `1.0.0`, explicitly update the project requirement after validating against the
release candidate.

LOT-36 will define the exact release-candidate baseline.

## 8. Python support

The current minimum supported Python version is:

```text
Python 3.11
```

The release matrix also qualifies Python 3.12, 3.13, and 3.14.

## 9. Check your codebase for deep imports

A useful repository check is:

```bash
grep -R "from pypagekit\..*\." .
grep -R "import pypagekit\..*\." .
```

Review matches against `PUBLIC_API.md` rather than replacing mechanically; some public subsystem
facades legitimately contain one dot, such as `pypagekit.build`.

## 10. Upgrade sequence

Recommended final migration sequence:

```text
0.9.0b1
   ↓
remove deep-import dependencies
   ↓
enable DeprecationWarning in tests
   ↓
validate plugins against extension API 0.7
   ↓
0.9.0rc1
   ↓
run complete tests/build/CLI workflows
   ↓
1.0.0
```

## Current migration delta

For supported facade-based `0.9.0a1` application code:

```text
required API rename        none
active deprecation         none
CLI command migration      none
plugin entry-point rename  none
minimum Python change      none
```

LOT-35 establishes the compatibility discipline; LOT-36 will freeze the exact 1.0 baseline.
